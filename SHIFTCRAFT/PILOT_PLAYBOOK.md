# SHIFTCRAFT | AI adoption pilot playbook

## 1. Discover
Interview engineering leads and developers. Map version control, CI/CD, review and incident workflows. Confirm approved AI tooling and data boundaries.

## 2. Select
Choose one bounded use case (for example, unit-test design on a non-sensitive repository). Document the current process and known pain points.

## 3. Baseline
Collect comparable cycle time, defect rates, review rework and developer-confidence data. Define metric ownership and collection methods.

## 4. Enable
Run the workshop, publish repository guidance, and pair developers with champions. Require normal tests and approvals.

## 5. Evaluate
Compare similar tasks, record failure modes, audit generated suggestions and collect developer feedback. Do not assume correlation proves causation.

## 6. Embed
Document working practices, maintain a review cadence and update guardrails as the tool and organization evolve.

## Example acceptance criteria
- No secrets or customer data exposed in prompts.
- All AI-assisted changes receive human review.
- Existing CI quality and security checks remain mandatory.
- Pilot outcomes include quality and developer experience, not just speed.
- Decisions to scale are based on evidence and stakeholder agreement.
