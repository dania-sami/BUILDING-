# SHIFTCRAFT ✦ AI Adoption Studio

**From AI curiosity to measurable developer impact.**

Built by **Dania Sami** as an independent, practical portfolio demonstration inspired by the **AI Adoption Specialist** role at Knowit Sweden.

## Open in one click

1. Unzip this folder.
2. Double-click `index.html`.
3. Explore the seven modules. No installation, Docker, accounts or API keys required.

The interface is responsive and works offline. The optional Google Fonts request requires an internet connection; system fonts are used otherwise.

## What you can actually do

| Module | Interactive capability |
| --- | --- |
| Mission Control | Explore the synthetic customer engagement and navigate the full journey |
| Readiness Scan | Change customer context and maturity scores, receive an updated readiness index and export a 12-week roadmap |
| Workflow Playground | Switch between test generation, PR review, refactoring and onboarding documentation; inspect prompts, outputs and review checklists |
| Prompt Architect | Select reusable Copilot-style instruction templates, copy and export them |
| Workshop Builder | Select workshop segments, see the agenda update and export it |
| Impact Lab | Change pilot assumptions, visualize before and after metrics and export a CSV |
| Trust & Governance | Choose guardrails and export a customer governance plan |

Changes persist in your browser using localStorage. Use **Reset demo** to restore the original scenario.

## The customer story

A fictional 12-person .NET/Azure commerce team has started experimenting with AI coding assistants. Their challenge is not whether AI can generate code. It is whether the team can introduce safe, repeatable practices and evaluate outcomes. SHIFTCRAFT guides a consultant through discovery, demonstration, enablement, coaching, measurement and governance.

## What this demonstrates

I designed SHIFTCRAFT around the actual responsibilities of an AI adoption consultant: diagnosing barriers, selecting concrete software-development use cases, writing effective instructions, coaching developers, keeping human review central, and measuring outcomes with an explicit baseline.

The included C# sample is a small, deliberately limited exercise for test-design discussions. The `.github/copilot-instructions.md` file shows how I would document repository-level guidance for AI coding tools.

## What it does NOT claim

- This is a **static, interactive simulation**. It does **not** call GitHub Copilot or any live AI API.
- All customer details, adoption figures, confidence scores and productivity metrics are **synthetic**, not results of a real pilot.
- Prompt examples and generated outputs are curated demonstration content, not model responses.
- The C# code is a teaching example, not a deployed production service.
- This is an **independent portfolio project**, not a Knowit product or endorsement.
- Readiness scoring is a transparent illustrative heuristic, not a validated organizational assessment instrument.

## Suggested real-world next steps

A real customer engagement would begin with stakeholder interviews, approved tooling and policies, a narrowly scoped pilot, actual repository-level Copilot instructions, developer coaching, and a measurement plan that tracks quality as well as speed. It would also require stakeholder agreement on what data can be shared with AI tools.
