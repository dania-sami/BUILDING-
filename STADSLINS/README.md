# STADSLINS | Urban Safety Research Lab

A standalone, original research portfolio prototype designed around the responsibilities of KTH's Research Student Assistant in Urban and Regional Studies (PA-2026-3771).

## Quick start
Open `index.html` in a browser. No installation is needed for the interactive spatial explorer and Swedish/English survey.

## Python pipeline
From the project folder:
```bash
python scripts/pipeline.py
python -m unittest discover -s tests -v
```
This validates the synthetic CSV, computes Haversine distances to fictional area centers, and generates `outputs/urban_safety.sqlite`, `outputs/validated.csv`, and `outputs/summary.json`.

## Python statistical analysis (no R installation required)
From the project folder:
```bash
python scripts/pipeline.py
python scripts/analysis.py
python -m unittest discover -s tests -v
```
The Python analysis replaces the former R script. It generates `outputs/python_area_time_means.csv`, `outputs/python_regression.json`, and `outputs/python_safety_by_area.svg`. It performs grouped statistics, illustrative ordinary least squares regression, and a boxplot without installing any extra packages.

## Survey
The survey is bilingual and works offline. Submissions stay in browser localStorage, not a remote database. Export local responses as CSV. No names, email addresses or exact survey coordinates are collected. This is not a production research survey; real distribution requires institutional approval, a data protection assessment, an appropriate consent/information process and secure infrastructure.

## Spatial accuracy
The map is a stylized geographic canvas, not a GIS basemap. Python uses real geographic distance calculations on **synthetic coordinates**. Area centroids are illustrative. No claims are made about actual safety in Stockholm.

## Open data integration plan
1. Identify suitable public geodata from Stockholm's open data portal, Lantmäteriet, SCB or OpenStreetMap; confirm licensing and provenance.
2. Record dataset version, coordinate reference system (CRS), coverage, update frequency and field definitions.
3. Reproject all layers to a common CRS before overlays or buffers (e.g. using GeoPandas/pyproj in an extended environment).
4. Geocode or aggregate responses only at a privacy-appropriate spatial resolution.
5. Document missingness, sampling limitations, uncertainty and reproducibility.

## Research limitations
All 240 sample observations are generated by a simulation with a designed relationship between lighting, activity, maintenance and safety. Thus regression associations are artifacts of the simulation, **not empirical evidence or causal estimates**. The Python regression treats ordinal ratings as numeric for demonstration and would require methodological scrutiny for real research.

## Project layout
- `index.html`: self-contained interactive experience and bilingual survey
- `data/synthetic_survey.csv`: synthetic research observations
- `scripts/pipeline.py`: validation, distance analysis, SQLite outputs
- `scripts/analysis.py`: Python summaries, model and SVG boxplot
- `tests/test_pipeline.py`: Python unit tests
- `docs/data_dictionary.md`: definitions and research protocol
- `outputs/`: generated artifacts

This is an independent portfolio project, not an official KTH research study.
